# Security policy

## Current support status

Business OS: Digital Clinic is under staged initial development and has no supported production release yet. The repository must not be treated as a deployed security product or as a promise of absolute protection.

## Report a vulnerability

Do not disclose exploitable details, credentials, personal data, or proof-of-concept payloads in a public issue.

Use GitHub private vulnerability reporting from the repository's **Security** tab when it is available. If private reporting is unavailable, contact the repository owner through the public GitHub profile and request a private channel without including sensitive details in the initial message.

Include, where safe:

- the affected commit or future release;
- the impacted component and configuration;
- clear reproduction steps with non-destructive test data;
- the observed and expected behavior;
- realistic impact and prerequisites;
- suggested mitigations, if known.

## Research boundaries

- Test only systems and data you own or are explicitly authorized to assess.
- Do not perform denial-of-service, destructive testing, persistence, social engineering, or access to other users' data.
- Minimize retained data and delete test artifacts after the report is resolved.
- Allow maintainers reasonable time to investigate and coordinate a fix before disclosure.

Good-faith reports that follow these boundaries are welcomed. This policy does not grant authorization to test third-party services or production systems outside the repository owner's control.
